# Autonomous Travel Agent (Plan-and-Execute Architecture)

Цей проєкт реалізує автономного туристичного AI-агента на базі фреймворку LangGraph. Замість стандартного підходу ReAct, агент використовує архітектуру **Plan-and-Execute**, що дозволяє йому розбивати складні задачі на кроки, працювати з базою знань (Agentic RAG) та зупинятися для підтвердження ризикових дій людиною (Human-in-the-Loop)

---

## Архітектура (Plan-and-Execute)

Система побудована у вигляді графа станів (StateGraph) і складається з трьох основних вузлів:

1. **Planner (`planner_node`)**
   * Отримує запит користувача та створює суворий, лінійний список кроків для досягнення цілі.
   * Задача — скласти ідеальний план (happy path), генеруючи виклики доступних інструментів (API) на основі їхніх описів.

2. **Executor (`executor_node`)**
   * Бере поточний крок із плану та виконує його. LLM самостійно вирішує, які аргументи передати в інструмент (наприклад, `search_flights`).
   *Містить логіку обробки переривань. Якщо інструмент позначено як ризиковий (наприклад, бронювання), Екзекутор призупиняє граф через механізм `interrupt()`.

3. **Replanner (`replanner_node`)**
   * Отримує результати виконання кроку, аналізує їх відносно оригінального запиту користувача і приймає рішення через структурований вивід.
   * Якщо інструмент повернув помилку, або користувач відхилив дію, Репланер генерує новий список кроків. Якщо план іде за графіком — пропускає далі. Якщо ціль досягнута — завершує роботу.

---

## База знань (Agentic RAG)

Проєкт використовує **Agentic RAG** на базі **ChromaDB**. На відміну від класичного RAG, де пошук відбувається на кожен запит користувача, тут агент вирішує, коли йому потрібна довідкова інформація.

* **Інструмент:** `search_knowledge`
* **Робота інструменту:** Застосовується для пошуку статичних знань (візові правила, поради щодо спорядження, культурні події, клімат).
* **Постобробка (Synthesis):** Щоб уникнути галюцинацій та забруднення контексту  нерелевантними даними з векторного пошуку, інструмент включає власну міні-LLM логіку. Вона аналізує знайдені документи, витягує лише потрібну інформацію і повертає обʼєднану відповідь

## Human-in-the-Loop (HITL)

Деякі дії є незворотними (наприклад, списання коштів за авіаквитки). Для них реалізовано механізм HITL за допомогою LangGraph `interrupt()` та `SqliteSaver` (Persistence).

**Як це працює:**
1. Виконнання доходить до інструменту `book_flight`.
2. Граф зупиняється (`interrupt`), зберігаючи свій стан у базу даних SQLite (`agent_state.db`).
3. Користувачу (оператору) виводиться повідомлення з параметрами транзакції.
4. **Сценарії реагування:**
   * Approve: Користувач підтверджує транзакцію (`Command(resume={'approved': True})`). Агент виконує бронювання і йде далі.
   * Reject: Користувач відхиляє дію та вказує причину (наприклад, "Зміни кількість пасажирів з 2 на 1"). Репланер читає цю причину, скасовує старий план, створює новий для 1 пасажира і повторює спробу.

## Аналіз результатів та можливостей

Під час тестування архітектура продемонструвала високий рівень автономності:
* **Самокорекція параметрів:** Коли базовий API-інструмент повернув дефолтні дані (1 гість, 1 ніч), Репланер помітив невідповідність із запитом користувача (2 гостя, 3 ночі) і змусив Екзекутора повторити пошук з правильними аргументами.
* **Динамічне перепланування:** При відсутності авіаквитків до цільового міста (Монреаль), агент успішно обробив умову "фолбеку" з оригінального запиту і самостійно побудував новий маршрут (до Ванкувера), знайшовши нові квитки та готель.
* **Стійкість до збоїв:** Завдяки `SqliteSaver`, агент здатен відновлювати свою роботу після критичного завершення процесу (наприклад, перезапуску сервера), продовжуючи виконання рівно з того кроку, на якому зупинився

## Інструкція із запуску

Клонувати репозиторій: git clone https://github.com/roman-ianivskyi/hw2_plan_execute.git.
Встановити залежності: pip install -r requirements.txt.
Налаштувати API-ключ: export OPENAI_API_KEY="...".
Перейти в директорію: cd hw2_plan_execute.
Запустити агента: python plan_execute.py
